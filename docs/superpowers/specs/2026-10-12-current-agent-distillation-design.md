# 当前 Agent 蒸馏模式设计

用户于 2026-10-12 确认：默认由安装 Skill 的当前 Agent 分析；网页继续负责上传、进度、结果和分享；上传后允许回聊天发送一次“开始蒸馏”。原 Codex / Claude Code 自动执行方式保留为可选。

本文是待最终审阅的书面设计，不是已实现、已通过跨平台验收或已完成整书蒸馏的证明。

## 目标与范围

- 默认使用当前会话的 Agent，不检查或强制安装 Codex / Claude Code，不由年年阅另行配置模型 API Key。
- 适用前提：宿主已加载 Skill，允许读写同一工作区和执行 Python 脚本，能访问助手启动的本地网页。助手补齐 Python / 文本 PDF 依赖；普通用户不执行命令、不编辑 JSON。
- 不承诺纯聊天网页、手机端、云端沙箱与本机共享文件；缺能力时说明原因，不自动改用付费后端。
- 保留原界面风格、解析、仓颉原规则、分批核验、结果契约、分享绘制与导出。只增加必要的任务交接状态和提示。
- 不实现任意 Agent 自动唤醒、MCP Sampling、各平台插件、OCR / DRM、书本 Skill 编译或新模型供应商接入。
- 当前模型仍会收到电子书正文，并消耗宿主账号的额度；不是完全离线推理或免费不限量服务。

## 用户流程

1. 用户让当前 Agent 打开年年阅。助手启动默认 `agent` 模式服务，打开实际 URL；不启动常驻 AI CLI 子进程。
2. 网页上传 EPUB / 文本 PDF / TXT / MD，服务检查类型、大小和可解析正文，持久保存任务。显示“已上传，等待当前助手开始”。
3. 网页提供“复制开始指令”，指令仅包含任务 ID 和最少的本地任务定位，不包含正文、凭据、令牌或可执行命令。用户在启动网页的同一聊天里发送该指令。
4. 当前 Agent 按 Skill 指引认领任务，读取每一阶段的规则、证据和结果要求，以自身模型完成分析，再通过固定辅助脚本提交阶段回复。
5. 服务执行原契约和来源检查，通过后保存有效阶段并准备下一阶段。Agent 在当前获准预算内继续，不要求用户逐阶段触发。
6. 正式结果回到原网页，自动刷新；复制、Markdown、离线 HTML、三种比例 PNG 和 ZIP 仍使用同一份分析对象。

“等待助手”不显示为模型正在处理。网页“刷新状态”只同步服务状态，不登录、不切换模型、不唤醒 Agent。

## 模式选择与兼容

- `serve_ebook.py` 新增 `--runner agent`，无参数时默认 `agent`。
- 原有显式 `--runner auto|codex|claude` 保留原行为，包括 `auto` 优先查找 Codex；仅在用户明确要求自动模式时由助手选择。
- 页面明确显示“当前助手分析”或实际 CLI 名称及各自触发方式；不笼统显示“已连接当前模型”。
- 不在已有任务中途隐式切换后端。切换由助手显式启动对应服务；历史任务保留原执行方式和验证说明。
- 保留读取旧任务的兼容性；新字段缺失时按旧 CLI 任务处理，不能把旧任务误认领为当前 Agent 任务。

## 架构与交接契约

复用 `ebook_pipeline.py` 的顺序调度和验证门，新增当前 Agent 的阶段交接实现，以及 `ebook_agent.py` 辅助入口。Python 只做解析、调度、检查和渲染，不代替模型生成语义结果。

辅助入口负责列出任务、认领、取下一阶段、提交回复和释放认领。助手使用这些固定入口，不让用户复制大型提示词或模型 JSON。无需另装模型命令行；这里的 Python 辅助脚本不是新的 AI 后端。

每条私有请求至少绑定：

- 任务 ID、尝试 ID、唯一请求 ID、阶段名和顺序号。
- 原书 `source_hash`、方向、规则 / 输入摘要、结果 schema 和执行身份。
- 有限认领期限、提交状态及用于拒绝过期回复的版本标识。

请求 / 回复保存在对应任务的私有工作目录。服务状态接口仅返回展示所需的元数据，不把待分析全文暴露到浏览器。助手提交的文件必须解析并验证，不能直接作为正式 `analysis.json` 发布。

一次尝试最多只有一个认领者和一个待提交阶段。同一请求重复提交相同已接受回复是幂等操作；冲突回复、越阶段回复、过期尝试、未知任务和撤销后的提交全部拒绝。

## 状态、中断与恢复

新增真实状态：`awaiting_agent`（待认领）、`awaiting_response`（已交接阶段，等待回复）。保留运行、成本确认、失败、中断、取消和完成状态；新状态加入单任务互斥和恢复检查。

- 未认领时不计模型阶段超时；页面显示等待，不伪造进度。
- 认领期限使用现有 `--stage-timeout`（默认 180 秒，允许 30–900 秒）。成功领取新阶段或提交回复后刷新期限；等待同一阶段回复期间不自动无限续期。过期撤销认领并显示中断，重新接手产生新尝试 ID；不永久占用假运行状态。模型输出是否已被宿主生成不等于服务已经接受。
- 同一执行身份恢复时重新检查有效阶段缓存；取消 / 重试生成新尝试 ID，旧回复不得污染新尝试。
- 服务重启后撤销旧认领，活跃任务标记中断。网页恢复只恢复可见状态，用户仍需在当前 Agent 中触发续跑。
- 网页取消立即撤销待接收阶段并阻止后续发布；不能保证停止宿主已经开始的模型思考，提示需要时同时停止助手。
- 无效回复进入私有诊断，任务明确失败并保留有效前序。不自动要求模型无限修正，不把无效回复当缓存。
- 沿用大任务成本确认。当前 Agent 模式使用“分析阶段数”而不是虚构的 API 调用数；用户确认费用 / 长时任务前不扩大工作。

## 缓存与执行身份

- 新模式使用独立 runner 身份，不更改 CLI 前序规则、提示词及原缓存键，不覆写或迁移历史 CLI 缓存。
- 当前 Agent 的身份记录宿主、可确定的模型和会话作用域。无法可靠获取模型时明确标为未知，默认按会话隔离，不猜测模型名。
- 身份字段是审计信息，不是账号认证或模型真实性证明。换模型 / 会话不能伪造旧身份以命中旧语义缓存。
- 同会话的失败 / 取消可复用重新验证后的有效阶段；模型未知的新会话只能重新分析，不能承诺跨会话无成本续跑。

## 核验和隔离边界

整书理解、五类提取、完整候选对齐、分批 V1 / V2 / V3、全局覆盖、RIA 和组织继续使用真实模型结果。候选分区、原文精确引文、关联来源和覆盖门槛不降低；缺口继续进入网页和所有导出。

当前 Agent 的同一会话已经读过能力卡，不具备原 CLI 每阶段独立上下文。继续执行的压力测试只能记录为**非隔离对照演练**：

- 不声称基线未读过能力，不声称独立盲测，不报告已证明任务增益。
- 实际回答、固定判据和失败结果仍保留；不能仅因演练通过就升级为原等级的 `validated`。
- 当前 Agent 模式的可执行方法保留来源检查结果，但最终语义状态至多 `needs_review`，原因明确为缺少隔离对照；原参考项仍为 `reference`，被拒绝项不重新升级。最终 `quality_status` 为 `needs_review`。
- 任务流程完成、结果可导出与内容完全核验分开显示。最终候选状态、任务覆盖审计、限制说明和所有导出必须一致，不只在网页加一句提醒。
- 原 CLI 模式继续使用原有隔离调用和压力测试标准；不受上述降级影响。

当前会话需要文件和脚本工具，不能沿用“所有工具已被强制关闭”的表述。电子书、用户方向和模型返回都是不可信数据；宿主只可按 Skill 指引读取本任务资源、调用固定辅助脚本、写阶段回复，不能执行书内指令、跟随书内链接、访问凭据或连接器。该约束是宿主指引，不宣称跨平台已强制隔离。

本地服务继续仅监听 `127.0.0.1`，保留 Host / Origin / 令牌检查。辅助入口解析绝对路径并限制到当前任务目录，拒绝路径穿越、符号链接逃逸和非 JSON 输入；正文与令牌不进入分享包、公开日志或 Git。

## 验收与成本边界

实现使用先失败后修复的测试，至少覆盖：

1. PATH 中无 Codex / Claude 时，默认模式仍可启动、上传和生成待认领任务，且不执行模型 CLI。
2. 受控阶段回复经过真实 pipeline 的契约 / 来源门，得到同源网页与导出；受控回复不是实际模型成功证明。
3. 错误引文、非法 JSON、遗漏候选、越阶段 / 过期 / 冲突回复均不缓存、不发布。
4. 单任务认领、重复提交、超时、取消后的迟到回复、服务重启和同身份续接按真实状态工作。
5. 成本确认不被认领绕过；等待助手时没有假进度；复制开始指令不泄漏令牌或正文。
6. 当前 Agent 模式的非隔离演练和 `needs_review` 在网页、JSON、Markdown、离线 HTML、PNG / ZIP 一致；历史 CLI 状态不被误改。
7. 原 CLI 核心、分批核验、服务器、发布资源清单和完整安装回归通过；新辅助脚本包含在发布包中。
8. 当前模式完成小文本真实会话验收后才报告该层通过；WorkBuddy / Trae 未实际跑过时仅标“待验收”，不由文档支持推断可用。

本次开发预算仅包括代码和受控 / 本地测试，不自动启动新的 AI CLI、整书模型续跑或跨平台账户操作。真实短文或整书的模型验收另列范围和调用预算，经用户确认后执行。此前整书未完成及旧预算边界不因本改造自动解除。
