# 年年阅 Skill 首版设计

## 1. 目标

将用户指定自然年的微信读书记录转换为一套本地、可追溯、可编辑的阅读年报：包含年度图谱、分享卡组、全部单书档案，以及用户提供合法全文后可继续生成的深度蒸馏和子 Skill。

首版采用全范围、分阶段交付。样例模式必须完整可运行；真实微信读书模式若受接口权限或返回结构影响，必须明确展示验证状态，不得用样例结果冒充真实账号结果。

## 2. 用户流程

1. 用户指定年份；未指定时询问，不擅自选择。
2. 系统检测 `WEREAD_API_KEY`：存在则尝试真实模式，不存在则说明并进入样例模式。
3. 拉取或读取数据，完成规范化、证据分级、主题聚合和书籍评分。
4. 生成 `selection-preview.md`，展示全年书目、前 20% 推荐和 3 本年度之书候选。
5. 用户确认或调整精选书及年度之书。
6. 生成年度数据、全部单书档案、图谱、可编辑卡片 HTML 和 PNG。
7. 用户确认文案与引用后，将本次输出标记为最终版。
8. 用户为某本书补充合法全文时，单独启动 E3 深度蒸馏；普通年报不自动执行。

默认只设置两个人工验收点：精选书确认、最终文案与引用确认。

## 3. 系统边界

### 3.1 首版包含

- 自然年年度报告。
- 样例模式与真实微信读书数据适配器。
- 分页、规范化、异常数据和空数据处理。
- E0–E3 证据分级。
- 前 20% 精选、3 本年度之书候选和可解释评分。
- 全部单书档案。
- 本地交互式 `atlas.html`。
- 年度卡组、三类单书卡 HTML 和 PNG 导出。
- 用户提供 PDF、EPUB、TXT 后的深度蒸馏和子 Skill 生成。
- 数据、隐私、引用、文件完整性与基础视觉验证。

### 3.2 首版不包含

- 账号系统、云存储、多人协作或自动发布。
- 自动下载、破解或抓取书籍全文。
- 将用户阅读数据上传至第三方服务。
- 未经用户确认自动生成最终分享内容。
- 没有全文证据时伪造作者观点或完整书评。

## 4. 架构

```text
用户请求
  ↓
SKILL.md 路由与授权检查
  ↓
数据采集层 ── 样例适配器 / 微信读书适配器 / 本地全文适配器
  ↓
规范化层 ── 年份过滤 / 去重 / 月份归档 / 来源索引
  ↓
证据层 ── E0–E3 / 引用来源 / 降级规则
  ↓
分析层 ── 评分 / 主题 / 节律 / 年度命题候选
  ↓
确认门 ── 精选书与年度之书
  ↓
生成层 ── JSON / Markdown / atlas HTML / 卡片 HTML / PNG
  ↓
验证层 ── 隐私 / 引用 / 完整性 / 尺寸 / 可读性
```

各层只通过版本化 JSON 数据契约通信，避免接口字段、内容判断和视觉模板耦合。

## 5. 组件设计

### 5.1 Skill 入口

`SKILL.md` 负责识别年度年报、单书卡和深度蒸馏三类请求，说明所需输入，并按实际任务读取对应 reference。入口不承载长篇模板或接口细节。

### 5.2 数据采集

- `collect_weread_data.py`：读取环境变量、请求数据、处理分页、超时和有限次数重试；日志不得记录 Key。
- `sample-data.json`：覆盖已读、在读、少笔记、无笔记、跨月和不同内容类型。
- 原始数据只保存在本次输出的私有中间目录；公开产物使用清洗后的数据。
- 微信读书接口封装在单一适配器内。接口变化不得影响后续分析层。

### 5.3 规范化与证据

`normalize_yearbook.py` 生成统一书籍、阅读事件、笔记、划线、来源和月度记录。每个可引用片段必须保存稳定来源标识。

证据等级：

- E0：只有书架记录或极少阅读痕迹。
- E1：存在阅读进度或少量划线。
- E2：阅读较完整，或有较丰富的划线、想法。
- E3：用户提供可合法处理的完整文本。

等级由可解释规则计算，并保存触发原因。人工可调高或调低，但调整必须记录。

### 5.4 筛选与内容

`score_books.py` 按阅读投入 20%、个人投入 25%、年度关联 25%、转折信号 15%、可复用性 15% 计算年度代表性分。所有分项和理由进入预览文件，用户可以改选。

`build_book_profiles.py` 为每本书生成：

- “这本书讲了啥”：仅在证据允许范围内概括问题、骨架和重点。
- “我的思考”：基于用户划线、想法、阅读行为以及与其他书的关系。

E0 内容必须缩短；E1 不输出完整论证骨架；E2 才可进入完整轻蒸馏和默认单书卡。

### 5.5 深度蒸馏

`build_deep_distill.py` 仅处理用户主动提供的 PDF、EPUB、TXT。它输出论证结构、方法、适用场景、限制、案例、反例和测试问题。

只有同时满足“可解释、可执行、可验证”的能力才生成子 Skill。生成物还需通过 Skill 结构校验和引用覆盖检查；失败时保留深度档案，但不生成子 Skill。

### 5.6 图谱与卡片

`render_yearbook.py` 基于同一份规范化数据生成：

- 年度书籍年轮。
- 月份、主题、完成状态和证据等级筛选。
- 单书详情及引用证据回链。
- 年度封面、节律、主题、年度之书、精选书和年度问题卡。
- 竖向线索卡、对页卡、折页卡三种单书版式。

视觉采用 3:4 暖纸张 Zine 体系。每年只有一个强调色；书封、线、节点、编号和页脚必须承载信息。禁止玻璃拟态、蓝紫科技渐变、套娃圆角卡片和无意义装饰。

`export_cards.py` 使用本地浏览器渲染 HTML 为 PNG。HTML 是主源，PNG 是可分享派生物。

## 6. 数据契约

核心实体包括：

- `Yearbook`：年份、汇总统计、主题、命题、强调色和验证状态。
- `Book`：书籍身份、元数据、进度、阅读事件、证据等级和来源。
- `Annotation`：类型、文本、时间、来源位置和所属书籍。
- `Score`：五个分项、总分、入选状态和解释。
- `Profile`：书籍概括、用户思考、引用列表和内容边界。
- `Artifact`：产物路径、类型、生成状态和验证结果。

真实模式、样例模式和深度模式使用同一输出 schema，并通过 `source_mode` 与 `verification_status` 明确区分。

## 7. 输出结构

```text
output/<year>/
├── atlas.html
├── yearbook-data.json
├── selection-preview.md
├── validation-report.json
├── cards/
├── cards-html/
└── books/<book-slug>/
    ├── profile.md
    ├── evidence.json
    └── deep/
```

内部缓存和原始响应不进入最终公开目录。任何输出、日志和 HTML 都不得包含 `WEREAD_API_KEY`。

## 8. 错误与降级

- 无 Key：提示进入样例模式，不把样例称为用户真实年报。
- 鉴权失败：停止真实数据读取，返回中文解决建议，不回显请求头或 Key。
- 分页部分失败：保留已获取数据，但标记为不完整，禁止生成最终版。
- 空书架或年度无记录：生成明确空态，不制造内容。
- 无笔记：允许输出阅读节律和书目，但降低证据等级。
- 缺少书封：使用有文字标识的中性占位，不虚构封面。
- PNG 导出失败：保留可编辑 HTML，并在验证报告中列出失败卡片。
- 全文解析失败：不进入 E3；保留错误原因和可重试输入要求。

网络请求只对瞬时错误做少量重试；鉴权、权限、数据结构错误不盲目重试。

## 9. 验证策略

### 9.1 自动验证

- Skill frontmatter、目录命名和未完成占位符检查。
- 数据契约和必填字段检查。
- 分页、去重、跨年过滤和空数据测试。
- 评分可重复、分项可解释、用户改选可覆盖默认值。
- 引用必须回到划线或用户提供文本。
- Key 与疑似敏感字段扫描。
- 产物清单、链接、HTML 打开和 PNG 尺寸检查。
- 样例端到端运行。

### 9.2 人工验收

- 预览页是否能帮助用户判断推荐结果。
- 年度命题是否自然、具体且有证据。
- 三种卡片是否适配不同内容形状。
- 手机尺寸下文字是否可读。
- 年轮是否随真实月份和书籍数据变化。

### 9.3 真实接口状态

只有在真实账号成功完成采集、生成和验证后，才标记为 `live_verified`。仅完成代码或模拟响应测试时标记为 `implemented_unverified`。

## 10. 分阶段实施与验收

1. Skill 骨架、数据契约和样例数据：通过 Skill 校验与 schema 校验。
2. 微信读书适配器、规范化和证据分级：通过分页、异常和隐私测试。
3. 筛选、单书档案和文案：输出可解释预览与完整档案。
4. 图谱、三类卡片和 PNG：样例端到端生成并完成基础视觉检查。
5. 全文解析、深度蒸馏和子 Skill：至少对一种文本格式完成端到端验证，其余格式明确验证状态。
6. 总体验收：运行全部自动检查，生成验证报告，分别说明已验证、未验证和依赖用户账号验证的能力。

每阶段完成后再进入下一阶段；不通过的阶段不得以占位结果宣称完成。

## 11. 完成标准

- 无 Key 时，一条命令可从样例数据生成完整目录。
- 有 Key 时，适配器能安全处理分页和常见失败；未实测时明确标注。
- 全部书籍都有与证据等级匹配的档案。
- 推荐结果可解释、可调整，年度之书提供 3 个候选。
- 图谱可本地打开，卡片 HTML 可编辑，PNG 为 3:4。
- 引用可追溯，不含 Key，不将模型记忆伪装成书籍证据。
- 有合法全文时可生成深度档案；只有通过能力化检查时生成子 Skill。
- 最终验证报告清楚区分通过、失败、降级与未验证项。
