# 年年阅改进说明：现代阅读杂志与小红书分享体验

日期：2026-09-30。基线：`main / d6bdd29`。

状态：**待用户审阅实施方案**。产品方向和两次确认流程已经确认；下述工程方案、建议默认值和验收目标需本次审阅后再实施。本文没有对应的代码改动、成图实测或真实账号验证。

## 1. 结论与目标

将年年阅的主要分享体验升级为：**围绕精选书单与真实感受，由内容驱动构图的现代阅读杂志卡组**。完整阅读图谱和单书档案继续作为私人记录保留。

优先解决三个问题：陌生读者看得懂、用户愿意分享、生成过程省事。数据准确和证据可追溯是交付前提。

### 用户已确认

| 事项 | 决定 |
|---|---|
| 首要价值 | 记录与分享，优先优化视觉、卡片和生成体验 |
| 首要场景 | 小红书图文，面向陌生读者 |
| 内容主线 | 精选书单 + 我的理由；少量年度数据开场 |
| 个人感受 | 选填；有笔记先整理，缺少时邀请补一句，允许跳过 |
| 视觉要求 | 现代阅读杂志；有创意、不规律、不模板化，好看优雅，排版自然合理协调 |
| 默认确认 | 第一次确认书目、感受与逐页内容；第二次确认封面 + 一张典型内页视觉 |

### 本轮范围

包含分享内容编排、逐页创作机制、确认体验、可靠导出和局部修改。保留现有采集、年度过滤、评分、证据分级和私人档案。深度蒸馏不进入本轮重做范围。

不新增账号系统、云存储、自动发布、第三方模型 API 或全文抓取。宿主 AI Agent 负责语义整理和创作，现有 Python 流程负责数据与验收。依赖缺失时给出可用降级结果，不自动安装软件。

## 3. 方案比较与推荐

| 路线 | 优点 | 代价 / 风险 | 判断 |
|---|---|---|---|
| 扩充固定模板库 | 快、容易测试与稳定输出 | 页面仍由模板决定，难满足用户要求 | 不作为主方案 |
| **AI 逐页创作 HTML + 统一视觉约束 + 自动验收** | 根据内容构图，文字可编辑，沿用现有导出工具 | 需补充创作指令和布局验收；耗时要实测 | **推荐** |
| 每页用图片模型生成 | 插画表现力强，容易探索视觉 | 中文、精确数字与局部改字成本更高，新增依赖 | 后续可选插图能力 |

推荐路线把创意放在每次实际设计中，把可追溯性和质量放在数据契约与验收中。不会建立“随机选择模板”或“随机坐标排版”的机制。

## 4. 分享内容设计

### 4.1 年度数据与个人理由

- 年度数据仅作为开场或有意义的转折，不把所有统计项目强塞进卡组。
- 精选评分继续用于候选排序；“前 20%”不决定分享页数。分享书目由用户确认，并可区别于完整档案中的精选书目。
- 每本分享书优先回答：这本书涉及什么问题、我的阅读里留下了什么、我为何愿意把它放进这次书单。
- 有用户想法时，可在保留原意的前提下整理；直接引用保持原文。
- 用户新增一句感受记录为“制作年报时补充”，具有独立来源 ID；不混入目标年度的原始笔记数量和阅读时间。
- 用户跳过感受且缺少笔记时，只呈现已有书目、简介或阅读行为，不写“改变了我”“强烈推荐”等替用户表态的句子。
- 明确选为年度之书可以写“我的年度之书”；不能从这个选择反推不存在的感受。

### 4.2 建议默认页序

建议普通数据量先提出 **6–8 页、3–5 本书**的方案，在第一次确认时由用户调整。此为产品默认值，不是小红书平台要求，也不是固定模板。

可用的叙事职责：封面、少量年度坐标、年度之书、代表书或跨书关系、个人感受、收束。每页有明确的读者问题与重点；材料不足的职责可以省略，相关书可同页对话，重点书可跨页展开。

少量阅读用 3–5 页讲清少数书的价值；很多精选书时先建议缩减分享子集，完整记录仍进入私人档案。用户坚持增加页面时，展示更新后的整套页序，不缩小文字硬塞。

标题、正文与话题作为同一包中的草稿交付；标题不虚构数字反差，正文不把划线内容写成用户认同，不自动发布。

### 4.3 来源规则

所有统计数字、书籍事实与直接引用绑定来源；模型推断明确标记，避免伪装成个人原话。来源 ID 不只检查存在，还检查所属书籍、类型、实际文本或数字是否对应。共享材料不足时缩短内容，保留 E0–E3 的原有输出上限。

## 5. 视觉设计：内容决定构图

### 5.1 一致的视觉语言

延续暖纸张、墨色与书籍年轮，强化编辑感。字体层级、正文可读性、基准边距、页码、强调色、书籍信息标记贯穿整套。纸张纹理减弱，不影响正文对比度；优先使用清楚的中文字体，记录实际字体及回退状态。

年轮可以在封面或收束页形成识别，其他页面使用节制的轨迹片段或不用年轮。数据图形必须有准确映射和可理解的含义，不能为了好看改变阅读统计。

### 5.2 每页独立构图

每页由宿主 Agent 写一段构图说明，明确：主视觉焦点、阅读顺序、疏密关系、对齐依据，以及与前后页的呼应。

可采用非对称、跨栏、错位、字号对比、局部出血、书封或书名组合、摘录大字、细线与局部空白。但文字主体和重要数字始终处于安全区；装饰出血不等于正文裁切。

这些是设计手法，不是必须轮换的版式菜单。相同逻辑的连续页可以保持构图，避免为了差异制造噪音。

内容驱动的例子：

- 一句确认过的强烈感受：大字与宽松留白成为焦点，书籍信息退到注释位置。
- 三本围绕同一问题的书：通过共同议题组成一组对话，关联依据能回到实际材料。
- 一段阅读节律：月份承担时间顺序，重点月份有真实数字支撑。
- 长书名与较长摘录：换行、扩栏或拆页，配合整页构图变化。

### 5.3 创作与验证分工

Agent 根据逐页内容与构图说明生成静态 HTML/CSS；共享基础样式只定义视觉语言和可读性底线。Python 不再按类别决定固定页面布局。

每页包含稳定页面 ID，以及标题、正文、引用、页脚等语义标记，供脚本定位和验证。HTML 不执行自定义脚本，不使用动态远程嵌入；图表使用静态 SVG。图片优先使用已获允许的本地素材；缺少书封时采用书名排版，不虚构官方书封。

文字图像、素材与字体加载情况可检查，HTML 保留可编辑源。不能因 HTML/CSS 属于创作产物而跳过内容与隐私验证。

## 6. 两次确认与完整流程

| 阶段 | 系统动作 | 用户动作 / 状态 |
|---|---|---|
| 环境预检 | 检查数据模式、浏览器、导出与字体依赖；明确截至日期 | 缺失依赖时给出降级选项 |
| 数据准备 | 沿用采集、规范化、证据分级、评分；保留原始数据 | 尚未确认 |
| 内容规划 | 提出分享书目、页序、完整卡片文案；邀请选填一句感受 | **确认 1：内容** |
| 视觉试做 | 完成封面与一张能代表主要内容密度的内页，并展示实际预览 | **确认 2：视觉方向** |
| 整套创作 | 按已确认文字与视觉语言完成其他页面 | 默认不重复询问 |
| 验收交付 | 自动检查 + Agent 逐页目检，提交完整图片、源文件与文案 | 可提出局部修改 |

用户只需在对话中表达选择，不编辑 JSON。Agent 将明确选择和时间写入记录，不把沉默、默认选项或超时视为确认。

第一次确认覆盖直接引用和个人感受，不另外增加默认的“文案确认”。第二次确认只代表用户认可试做页与视觉方向；完整卡组由 Agent 检查，不宣称用户已逐页审批。

内容修改使受影响的内容确认失效；仅改整体视觉时回到第二次确认。纠正技术性溢出且未更改已确认文字与风格时，可直接修复受影响页。

### 版本与状态

确认记录绑定内容版本或哈希、试做页版本与视觉规范版本；渲染结果绑定实际源文件及素材版本。最终卡组不能混用旧图片和新 HTML。

分享模式建议采用三个独立状态：

- 内容：`draft / approved`。
- 视觉方向：`pending / approved`。
- 交付：`draft / html_ready / share_ready / failed`。

只有确认有效、数据完整、所有图片与源文件对应、自动验收和整套目检通过，才进入 `share_ready`。HTML 可用但 PNG 缺失时只能是 `html_ready`。样例始终带样例标记；不完整真实采集只能预览，不能生成可称为完成版的分享包。

现有 `publication_status` 的兼容映射在实现时保留，不能用它代替上述分享状态，也不表示已在外部平台发布。

## 7. 工程调整与输出契约

### 7.1 最小模块边界

1. **现有数据模块**：继续提供可信的年度数据和来源，不负责排版。
2. **分享规划与确认模块**：接收宿主 Agent 编排的逐页内容、可选感受和确认记录，检查来源与选择一致性。
3. **逐页创作规范**：指导宿主 Agent 设计静态 HTML，记录构图目的、阅读顺序与视觉版本，不新增模型网关。
4. **渲染与验收模块**：等待字体与图片、截图、检查尺寸与布局、生成验证报告。
5. **输出与修订模块**：版本化保存、局部重生成、整体发布已验证产物，保留失败原因。

原来的 CLI 调用和旧卡片格式保持兼容。新增分享模式采用独立清单与状态；验证器分离通用数据检查、旧卡组检查和分享卡组检查。新分享模式允许同页多本书和同书跨页，不继续强制“一本书一张卡”。每次新分享任务不必重复生成一套旧式卡组。

### 7.2 建议新增契约

在原数据 schema 之外新增版本化分享契约，避免破坏现有 `yearbook-data.json`：

- `share-plan.json`：受众、时期、分享书目、逐页标题与完整文字、来源引用、可选感受、构图目的、可选图片、稳定页面 ID。
- `share-approval.json`：内容确认版本、明确的用户选择与时间、视觉试做页与方向的确认版本。
- `share-manifest.json`：逐页源文件、图片路径、源文件/素材版本、渲染状态与验证结果。
- `share-validation-report.json`：数据、来源、确认、布局、文件、目检各项状态；未验证项明确列出。

完整私人数据与原始采集不进入 PNG 文案包。个人来源 ID、评分、证据等级保留在私人档案与验证报告；分享图只显示自然语言信息以及必要的样例、草稿或截至日期标记。

### 7.3 建议交付结构

```text
output/<year>/
├── atlas.html
├── yearbook-data.json
├── books/<book>/profile.md 与 evidence.json
└── share/
    ├── share-plan.json
    ├── share-approval.json
    ├── share-manifest.json
    ├── share-validation-report.json
    ├── caption.md
    ├── source/<page-id>.html
    ├── images/01-cover.png、02-....png
    ├── contact-sheet.png
    └── revisions/<revision-id>/...
```

用户主要拿 `images/` 与 `caption.md` 发布；`contact-sheet.png` 用于看整套节奏，源文件用于修改。发布动作仍由用户操作。

建议首版保持现有 **900×1200、3:4**，不增加分辨率选项。核心正文建议至少 30px，必要的辅助信息至少 24px；原有 20px 正文底线不足以保证手机可读。最终以约 375px 展示宽度下的实际检查决定是否需要扩大或拆页；不能靠持续缩小字体完成验收。这些是待验证的设计约束，不是平台规定。

## 8. 异常、返工与成本控制

| 情况 | 处理 |
|---|---|
| 年度尚未结束 | 显示“截至某日期”，统计只到真实可用日期，不暗示完整全年 |
| 无 Key | 提供明显标记的样例流程，不冒充用户数据 |
| 采集不完整或缺少年度指标 | 标注缺失；可以预览，禁止完成版；未知不当作零 |
| 年内零阅读 | 给出真实空态或其他周期选项；不强制选年度之书、拼凑分享页 |
| 只有 1–2 本书 / 没有个人想法 | 减少页数、选填感受；不强行认知变化或跨书关系 |
| 超长书名、摘录或多个重点 | 先改构图、换行与拆页，修改文案需退回内容确认 |
| 字体或书封缺失 | 明确回退字体；书封使用书名排版；失败素材不留破图 |
| PNG 导出不可用 | 保留 HTML 和计划，标为 `html_ready`；不宣称分享图完成 |
| 用户改一页 | 定位页面 ID 和依赖，只重做受影响页；整包重新检查映射 |
| 自动检查失败 | 最多两轮针对性修复；仍失败则保留草稿与明确原因，停止反复重跑 |
| 要求更换整体风格或大幅增页 | 先给更新后的范围与预估成本，再返回对应确认点 |

预检在创作前执行；可缓存的采集与分析结果复用，视觉修改不重新采集账号。基于源文件、字体、图片与渲染设置决定页面缓存是否有效；全部产物通过后才替换当前版本。

保留上一份有效成品；失败尝试存入独立修订目录。外部手改导致源文件哈希不匹配时标记需重新渲染，不静默覆盖或沿用旧 PNG。

不先建设图库、主题商城、复杂网页编辑器或自动排程。生成耗时记录网络采集、内容规划、视觉创作和渲染四部分；未建立基线前不承诺总耗时。

## 9. 验收与指标

以下为建议验收目标，不代表当前已达成，也没有用户研究数据支持。

### 必须满足的工程验收

- 所有事实、数字与引用来源覆盖率 100%；个人补充与原始记录可区分；确认版本与实际产物一致。
- PNG 与源页面一一对应、顺序正确、尺寸正确；无旧图残留混入新包；导出失败不进入 `share_ready`。
- 页面正文、标题与页脚无裁切和非预期重叠；字体、图片加载完成；语义边界检查允许明确标记的装饰出血。
- 私人完整档案与既有关键测试保持可用；数据缺失和零阅读不能靠虚构补齐。
- 使用短内容、长标题、长摘录、无感受、1–2 本书、较多书目、无书封、采集不完整和重生成等场景验证。
- 每套图片在缩略图、约 375px 手机宽度、原尺寸三个尺度检查；Agent 逐页目检，不只检查联系表。

### 创意与编辑验收

- 封面能说明“谁的哪一段阅读记录、读者为什么继续看”，没有套用泛泛年度鸡汤。
- 每页焦点与阅读顺序清楚；非对称有对齐依据；留白和密度服务具体内容。
- 全套有一致字体、墨色与注释语言，同时按内容形成疏密和尺度变化。
- 每种明显构图变化都能说明内容理由；不要求所有页面不同，也不以模板数量衡量创意。
- 3 套不同题材样例由各自内容产生不同的整体节奏；如果只更换书名、颜色而构图和重点没有响应内容，需返工。

### 建议的小规模产品验证

首轮邀请 5 位目标用户自愿试用，不自动联系或发消息。记录：是否无需手改 JSON 即可完成、内容和视觉确认次数、返工页数、完成后是否愿意直接分享。

建议目标：正常流程两次确认；至少 4/5 位认为能表达自己的阅读记录且愿意分享；至少 4/5 位陌生读者在 5 秒看封面后能复述核心主题。样本很小，仅用于发现问题，不推断总体偏好。

点击率、收藏率和互动率只在用户实际发布并提供数据后分析；本轮不把其提升当作已经验证的结果。

## 10. 实施顺序与文件范围

### 第一阶段：内容与确认链路

更新 `SKILL.md` 和 references；定义分享计划、用户补充、两次确认与来源契约；调整 `run_yearbook.py` 的分享状态编排。先验证无感受也能诚实规划、用户无需改 JSON、内容确认不会被默认伪造。

### 第二阶段：创意构图与视觉试做

增加逐页构图指导和共享视觉基础；使分享模式接收 Agent 设计的静态 HTML；更新 `render_yearbook.py` 的入口边界，旧版渲染保持兼容。先用同一份样例完成封面与一张最能暴露长文/密度问题的内页，按确认方向完成一套。

### 第三阶段：导出、验收与修订

改进 `export_cards.py` 的字体、图片等待与错误处理；拆分 `validate_yearbook.py` 的数据、旧卡组、分享包检查；增加版本映射和局部重生成。测试防裁切、旧 PNG 混用、修改确认失效、失败不覆盖成品。

### 第四阶段：完整样例与真实账号验收

完成 3 套不同内容形状的样例，展示整套与联系表；补齐 README、依赖和使用说明。真实账号只在具备可用 Key 且用户要求试跑时执行，单独报告真实数据验证结果。

每阶段只检查本阶段实际风险；不重写采集器、评分公式、全文解析和深度蒸馏。详细实现计划在本文获确认后编写。

## 11. 本轮方案自检

- 固定的是视觉语言与质量底线，页面构图由内容与 Agent 创作决定；不会把“不模板化”退化为随机轮换旧版式。
- 两次确认明确对应内容与视觉方向，默认无第三次确认；变更已确认内容时只退回受影响阶段。
- HTML 就绪与 PNG 就绪分开，不完整数据、未确认版本和渲染失败不能成为完成版。
- 分享子集与完整档案分别记录，少书、无笔记和长文均有降级路径。
- 模型编排采用宿主 Agent，脚本负责数据与验证；不依赖未定义的新模型 API。
- 来源研究、建议默认值、用户决定和验收目标已区分；未做的验证没有写成通过。
