## 参考源码及结论

参考：[kangarooking/cangjie-skill](https://github.com/kangarooking/cangjie-skill)，入口版本 2.5.0；调研时 main 为 `a28de55ba881b9928956a55048f743f7a9e3b23e`。实现时应记录实际采用的固定提交和文件。

已定向读取：SKILL.md、LICENSE、整书理解、三重验证、RIA 能力卡、压力测试、五类 extractor、DIGEST 模板，以及 `build_chunks.py`、`compile_single.py`、`cangjie.py`。

值得吸收的机制：

1. 先理解整书的结构、主张、论证与局限，再提取能力。
2. 分别提取框架、原则、案例、反例、术语；框架与原则覆盖全文，局部检索保留相邻上下文。
3. 验证来源充分性、可执行性和任务增益。可以跨章节合并证据，不以出现次数或作者独创性筛掉完整方法。
4. RIA 能力卡包含原文、解释、案例、使用时机、执行步骤、边界。
5. 单一结构化能力包生成读者精华和可调用入口，避免不同产物相互矛盾。
6. 测试实际输出、缺输入处理和错误场景；格式通过不等于语义验证通过。

源码中的 Python 工具处理确定性操作，蒸馏由宿主 AI 助手完成。`cangjie.py compile` 需要已生成的能力包，不能直接把电子书变成高质量蒸馏。

当前参考仓库 LICENSE 为 MIT。借用实质性源码或模板时保留许可与来源说明；不把同名的“人物思维蒸馏”项目当作本次参考。

## 用户流程

1. 安装 Skill 后，用户让助手“打开年年阅”。助手检查运行依赖及可用 AI 执行入口，启动本地服务并打开网页。用户无需执行命令或填写 JSON。
2. 在网页“电子书精华”区点击“上传电子书”，选择 EPUB、PDF、TXT 或 MD。解析文件元数据后直接按整书精华模式开始处理；用户可选择性补充应用方向。
3. 网页依次显示“解析正文 → 理解全书 → 提炼与核验 → 生成结果”，显示已处理章节，不虚构剩余时间或百分比。
4. 结果在同一网页展示：整书概览、核心观点/方法、关键案例、局限、术语和来源。用户可复制全文或单条内容。
5. 点击“做成分享图”，选择内容及 1:1、3:4、4:5 比例，预览后导出单张 PNG 或组图 ZIP。长内容自动分页，不能静默截掉核心内容。

电子书精华流程可以独立运行，不要求先连接微信读书、不要求选择年报年份。用户指定关联某本已有档案时，使用已核实的 book_id 关联。

本次上传和开始蒸馏即授权正常单书处理；不把原 Cangjie 的多轮聊天确认照搬进网页。批量处理、额外付费模型接入或显著超出普通单书成本时才针对实际情况另行确认。另行安装生成的书本 Skill 或改变年鉴视觉时，遵循该行动的已有授权。

## 网页背后的运行方式

当前年鉴是静态单文件 HTML，能浏览、复制和导出图片，但没有 AI 调用连接。新增功能需要本地运行服务：

`浏览器选择文件 → 本地服务解析与分块 → AI 完成语义蒸馏 → 本地服务核验和保存 → 网页显示结果 → 浏览器生成分享图`

默认由启动 Skill 的助手选择本机可用且已登录的 Codex/Claude 非交互执行入口。模型沿用执行入口当前配置；不能宣称它与当前对话共享上下文或必然能复用桌面端登录。检测或实际认证失败时，展示连接提示，不能假装已开始蒸馏。用户指定模型接口时可使用独立适配器，但不自动要求购买 API Key。

已核实本机 `codex exec --help` 和 `claude --help` 存在非交互与结构化结果选项；尚未执行付费模型任务或验证认证复用。

本地服务负责文件接收、解析、任务队列、分阶段 AI 调用、结果校验和保存。网页负责进度展示、结果浏览、选择、复制和图片导出。先支持单任务处理，包含取消、失败重试、断点续跑和刷新后恢复结果；失败阶段不展示为已完成。

本地服务只监听本机，并校验浏览器请求来源；电子书内容作为分析资料，不作为系统指令。调用宿主 AI 时使用受限执行方式，不执行书内脚本。模型凭据留在本地运行环境，不写入网页和导出文件。

蒸馏结果可保存为独立 HTML：服务关闭后仍可浏览、复制和导图；继续上传并生成新结果时需要由 Skill 再次启动运行服务。按按钮时要明确提示当前连接状态。

## 模块设计

### 1. 正文接入与定位

支持 EPUB、TXT、MD 和可提取文本的 PDF。

- EPUB 按 OPF spine 的正文顺序读取，保留章节、文件路径、段落定位；不按 ZIP 中的文件顺序拼接。去掉脚本、样式和导航噪声，不执行书内代码或访问书内链接。
- PDF 保留页码；空白页、扫描内容、无法解析的图表要明确记录。缺少必要文字或公式时不声称完成整本书。
- TXT/MD 支持常见编码和中英文标题，保留原始行范围和段落来源。
- 生成版本指纹、正文元素和结构感知分块。长段落可以拆块，正文不静默截断。
- 依赖按格式使用；普通 TXT/MD/EPUB 不应被 PDF 依赖阻塞。

本期不包括扫描 PDF OCR、DRM 解锁和电子书搜索下载。

### 2. 整书理解与五类提取

由本地服务调度 AI 执行入口按需读取分块，形成主旨、章节关系、核心命题、论证链、作者局限和关键任务清单。它是独立执行任务，不依赖用户手动回到对话继续操作。

默认单个助手按五种视角完成提取，不固定启动五个子代理。保留逐块覆盖状态，分块结果再进行跨章节合并和去重。章节、案例与主题的数量由正文决定，不凑数。

文学、传记等内容先提炼主题、叙事结构和有依据的观察；不为生成方法卡而强行改写成操作规则。

### 3. 验证与统一能力包

结构化记录候选的出处、限定范围、步骤、输入输出、边界、任务演练及判定理由。区分可执行方法、参考内容、待核查内容和排除项。来源中的步骤、单位或边界可跨段落合读，不能靠常识补成作者原意。

精华报告与方法卡从同一能力包产生。每条引文回查正文，说明章节/页码/段落来源；分开记录原文、助手解释、合成演练。用户的阅读笔记保留个人表达属性。

### 4. 精华交付与可选书本 Skill

默认面向用户交付网页内可浏览和导图的精华结果，下面文件用于保存和继续处理：

- `DIGEST.md`：面向读者的精华，讲清核心问题、主张、方法、关键案例、局限和适用条件。
- `BOOK_OVERVIEW.md`：整书骨架与覆盖说明。
- `GLOSSARY.md`：作者语境下的术语含义。
- `methods/`：有完整出处的 RIA 方法卡。
- `analysis.json`：统一结构化结果及引用索引。
- `validation-report.json`：解析、覆盖、引文、格式与语义核查状态。
- 可独立打开的结果 HTML：包含当前蒸馏结果及复制、分享图导出能力，不内嵌正文全文或模型凭据。

输出放在 `output/books/<book-slug>/deep/`；已关联年度档案时可放其现有 deep 目录。与旧 profile 输出需要时保留兼容摘要。

用户要求“把本书做成 Skill”时，再生成一个书本路由入口及对应方法卡，不默认安装、不自动发布。没有足够的可执行方法时仍交付读者精华，解释不能编译的原因。

### 5. 长书与断点续跑

保存源文件版本、阶段、已读分块和待处理缺口。中断后复用有效结果；源文件改变时使相关结果失效。处理前检查全文长度与计划读取规模，预计显著超过普通单书任务成本时说明范围并按用户约定暂停，不静默扩大代理或外部模型调用。

## 验收标准

1. EPUB 章节顺序正确；PDF 页码可回查；TXT/MD 兼容常见标题和编码。
2. 长文本、超长单段、末章以及跨章节完整方法都纳入覆盖检查，不能只处理开头或固定数量的候选。
3. 注入式正文仅作为书籍内容，不改变 Skill 工作流程。
4. 引文可在指定来源位置找到；虚构书中案例、伪来源和未解析公式不得进入已验证结果。
5. 两条完整方法加一条弱候选，完整方法仍能交付，弱候选明确记为参考或待核查。
6. 文学类、零可执行方法和部分解析的输入都有合理精华输出与准确的范围声明。
7. 使用合成样本检验解析与契约，再用用户提供或公版且适合的完整书籍做一次真实蒸馏；记录实际语义结果，不以单元测试代替质量验收。
8. 可选书本 Skill 做正常、缺输入、误触发/边界任务测试，生成链接、frontmatter 和资源完整有效。
9. 中断续跑复用有效结果，失败不留下虚报完成的正式产物；现有 HTML 年鉴与分享测试通过。
10. 浏览器实测上传、阶段进度、取消/失败重试、刷新恢复、结果复制、图文预览、PNG/ZIP 导出；导出页数与当前选择一致。
11. 服务未运行、AI 未连接、文件不支持、扫描 PDF 和超出处理预算均有可理解的网页提示；不能永久显示生成中。
12. 用真实可用的 AI 执行入口完成一次“网页上传 → AI 蒸馏 → 页面结果 → 分享图下载”，只用假适配器测试不构成端到端通过。

## 开发顺序

确认本设计后：同步最新基线 → 本地服务及 AI 执行连接 → 正文解析与分块 → Cangjie 式理解、提取与验证 → 网页上传、进度和结果 → 复制与分享导出 → 单书端到端实测和现有功能回归 → 更新安装发布清单与说明。

设计只定义基本可用的核心效果。尚未做源码执行或蒸馏效果对比，不承诺已经复现 Cangjie 的全部能力。
