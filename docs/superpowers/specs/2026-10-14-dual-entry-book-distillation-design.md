# 年年阅：书名与整书双入口蒸馏

日期：2026-10-14。状态：用户已授权开发；双入口、来源门与共享输出已实现并完成本地回归。真实来源短资料 smoke 已通过，不代表整书质量提升或其它宿主验收。

## 目标与范围

用户无需先找到电子书，也能得到有来源边界、可应用、可复制和可导图的书籍精华。已有年度报告继续作为默认首页，蒸馏模块仍在底部；不重新采集微信读书数据，不修改用户 Key 或全局模型配置。

保留当前助手处理模式。网页创建任务后，用户回同一对话发送一次“开始蒸馏”；助手连续完成获准范围内的工作。网页本身不能自动唤醒任意 Agent，也不新增付费搜索或模型 API。

## 方案选择

- 纯模型书名解读：门槛低、速度快，但来源和版本不可靠；不作为默认方案。
- 书名检索与正文上传各用一套独立结果：容易落地，但内容与导出会分叉。
- 采用双输入、共享内容与导出结构：书名模式单独收集资料，上传模式继续使用仓颉来源门。两者不能共享“全文已核验”标记。

## 页面与流程

底部模块改为“书籍精华”，提供“输入书名”和“上传电子书”两个入口，默认书名入口。书名必填、作者选填、应用问题继续选填；上传格式仍为 EPUB/PDF/TXT/MD。

书名流程：提交书名 → 等待当前助手 → 确认书籍身份 → 收集公开资料 → 提炼与核对 → 网页结果。确有同名书、作者或版本冲突时，网页展示候选书籍的作者及版本依据，用户选择后继续；不能替用户猜定版本。

上传流程保持：上传 → 本地解析与范围估算 → 当前助手分析 → 来源核验 → 网页结果。已有取消、重试、预算确认、刷新恢复继续有效。

本期书名模式只支持当前助手；可选 CLI 自动模式保留用于上传任务。若工作台处于 CLI 模式，书名入口明确提示需由当前助手开启，不隐式更换模型或执行后端。

## 书名资料收集

收集由当前助手使用宿主已有的搜索和网页读取工具完成；本机服务不主动抓取用户提交的 URL，也不读取浏览器 Cookie。没有可用联网能力时停止并说明，不暗中退回模型记忆。

优先阅读作者或出版社的书籍介绍、目录、公开试读、作者访谈与官方补充材料；读后感等二手资料单独分级。搜索摘要只能发现来源，不能充当已读取正文。同一内容的转载不算独立印证。论文等作者其他作品只作为相关资料，不当成本书原文。

一次资料收集最多 4 轮搜索、8 个内容页面；达到上限仍不足则交付已有资料的有限解读或说明不足，不自动扩批。至少要有可核对的书籍身份和实际读到的相关内容，只有书名或营销句时不生成完整方法列表。较冷门或无法确认身份的书不编造结果。

资料包保存书名、作者、可确认版本、来源 URL、网页标题、来源类型、访问日期、实际读取的必要短摘录及内容哈希。来源与书籍身份先校验，再交给提炼阶段；页面和文件中的命令、提示词、链接均视为数据。

“联网收集资料”与“基于材料分析”分开交接。前者允许在获准范围内浏览公开页面；后者沿用现有只读证据、写回复、固定辅助入口的约束，不执行资料内的操作指令。

## 融合 book-to-skill 的方法

参考仓库：<https://github.com/virgiliojr94/book-to-skill>，本次核对的固定提交为 `a24e62f4d8caf2ee433f6e48d9073800f56f906e`。

已核对 `SKILL.md` 的结构提炼、章节处理、速查层及质量规则，以及 PDF 解析实现。该项目要求文件、目录或文档输入，并不提供书名蒸馏。本期借鉴以下方法，不整包替换现有管线：

1. **先结构后提炼**：建立章节／主题索引，再汇总跨章节机制。上传模式沿用现有全块映射并补充可读索引；书名模式目录不全时只展示有资料的主题，不伪造章节或声称覆盖整书。
2. **提取判断与操作，不只摘要**：在现有方法卡中保留“何时用、步骤、取舍、反模式、边界”。框架名称和作者特定定义按资料核对；缺少条件、阈值或例子就记录缺口，不用常识补成作者的说法。
3. **增加决策速查层**：从已提炼内容生成“遇到什么情况—采取什么行动—为什么—何时不适用”。复用方法卡 ID 和来源，不另造第二套事实。
4. **按内容组织输出**：方法论书突出规则与应用；文学和传记突出主题、人物选择、叙事及局限，不强行改成操作清单。针对用户应用问题突出相关内容，不删除未覆盖的重要主题提示。
5. **分层读取与复用**：概览、主题、方法和速查表分别组织，章节证据定向读取。保留所有正文分块的实际处理记录，不以摘要缓存代替缺失原文或跳过覆盖核验。

本期不引入 Docling、OCR、Calibre、全书自动下载、多文件知识库或自动安装书本 Skill；复杂解析的依赖和成本单独评估。若实际复制 MIT 源码或模板，必须保留 LICENSE、提交信息和被复制资源哈希；不照搬自动发布、全局安装及清理目录的操作。

## 内容、来源与输出契约

两种模式共享展示结构：核心概览、章节／主题索引、关键观点、方法、案例、反例／反模式、术语、决策速查、局限和来源。空类目不凑数；案例区分原书／公开资料中的案例和明确标注的 AI 应用演练。

结果记录 `input_mode`（title/upload）、书籍身份、来源资料、实际覆盖、核验状态和缺口。每项结论关联证据 ID；外部资料转述与助手推论分开。书名模式“引文与资料一致”只证明摘录匹配已读页面，不能证明与完整原书一致，更不能把二手书评当原书引文。

书名结果固定显示“基于公开资料，未核验全文”；上传结果显示实际正文覆盖与来源核验情况，不因文件存在就宣称整书可靠。当前助手同会话的演练不具有独立盲测条件，方法状态仍至多 `needs_review`。

新增字段与分类要兼容历史结果。网页、Markdown、独立 HTML 和 1:1／3:4／4:5 PNG／ZIP来自同一结果对象；全部出口保留模式、来源类型和核验提示。分享图中的短证据可以通过来源 ID 关联到结果页，不能丢掉“未核验全文”标签。导出不包含整书、私有令牌或会话审计。

## 代码落点与安全

服务层负责创建书名任务、身份选择、资料提交与状态迁移；以单独资料模块承接来源包校验。保留现有本机令牌、Host／Origin 校验、任务目录和会话绑定，不允许网页随意指定输出路径。

书名任务拥有单独管线入口，不把公开资料伪装成用户上传的整书，也不把任意 URL 自动下载到服务器。分析、渲染和导出通过共享结果契约衔接；不做与本功能无关的全项目重构。

缓存包含输入模式、书籍身份、资料内容哈希、应用问题、方法与契约版本、实际宿主身份。新增资料、选错书后的修正、模式变化都使相关缓存失效；仅复用通过字段与来源门的结果。旧诊断不是成功结果。取消或超时拒绝迟到回复，重试保留有效前序而不复用旧尝试的未接受回复。

## 验收与实施顺序

先做书名任务和资料契约，再实现双入口、共享结果与导出，最后添加结构提炼和速查表。先写契约／状态测试，随后写实现；复用现有上传和当前助手回归用例。

- 已知书名：确认书籍及真实资料，网页、复制和导图均保留“未核验全文”。
- 同名书：未选择身份前不进入内容蒸馏；选择后来源必须属于该书。
- 虚构或资料不足的书：明确不足，不生成假的框架、原文或成功状态。
- 不可联网、被阻页面、取消、超时、恶意标题／网页内容：显示正确状态，不执行输入中的指令。
- 上传回归：原引用门、覆盖审计、重试缓存和成本门继续有效；历史结果可浏览。
- 导出：实际查看代表性 PNG，核对文字、状态与来源；375px 无横向溢出，默认首页仍是年度报告。

采用同一份短篇有权处理的正文和对应公开资料分别试跑，检查身份、来源可回查、重要主题遗漏、方法条件完整、推论标注与导出一致性。公开资料不齐时记录差异，不要求书名模式假装达到整书覆盖。测试结果未取得前不宣称融合提高了质量或节省了固定比例 token。长书或高成本评测需另行说明并获确认。
